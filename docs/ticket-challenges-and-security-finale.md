# Ticket challenges and security finale

New one-hour workshops keep five eight-minute rounds and the existing ticket count. All colours share the three-active-ticket limit. Peer checks consume no slot.

Each owned ticket offers an optional thematic quick challenge: network setup, venue safety, poster completeness or safe power restoration. A wrong answer changes nothing. The server validates owner, village, phase, crisis state and answer. Success removes 20% of the remaining work once per ticket: progress 40 becomes 52. This is a work reduction, not a permanent speed multiplier. Releasing/reclaiming, reconnecting and retries never grant it again. Preparation and an independent teammate check remain mandatory. The UI keeps the challenge expanded across polling and labels whose turn it is.

In round five, the simulated Digital City message offers a village-to-city upgrade. Viewing or email prefetching alone cannot impose a penalty. An explicit claim on the linked page costs the village EUR 1,000 and three trust, once per participant during active peer-workshop round five. Global pause and closed rounds block the penalty. Host participant monitoring separates page opens from penalized claims. No credentials or payments are collected. The page explains the impersonation and outcome.

Closing round five in a new peer workshop ends the session atomically, saves personal certificates with name, role and village results, and queues genuine Digital Village certificate/report emails for at least one minute later. This delay is a server queue schedule, not a guarantee of inbox arrival. Reports and queued report emails survive a confirmed session reset. Old sessions keep host-controlled completion and do not gain the new penalty rule.

The certificate uses the existing private report page, clearly headed Certificate of participation. There is no additional PDF attachment. Brand names, SMTP configuration, database location and domain automation are unchanged.
