# Подготовка SMTP и запуск

## Если игра уже работает на Raspberry Pi

Не заменяйте существующий `.env` целиком. Сохраните `ADMIN_PASSWORD`, `PIN_PEPPER`, `DB_PATH`, `PORT`, `PUBLIC_BASE_URL` и текущий Funnel. Сначала сделайте штатную резервную копию: `node deploy/backup.mjs`.

Из `smtp.env.example` перенесите в существующий `.env` только настройки SMTP. Для Gmail нужны адрес аккаунта и **пароль приложения**, созданный для аккаунта с двухэтапной проверкой, а не обычный пароль Google. `DEV_EMAIL_OUTBOX=0` включает реальную доставку. Не публикуйте файл с паролями в GitHub.

Обновление выполняется после проверки и слияния PR существующим процессом выпуска. Эта доработка сама не меняет Pi, службу, DNS или Funnel. Для штатного обновления используйте `bash deploy/pi-launch.sh --apply`; режим `--funnel` для этой доработки не нужен.

## Новая локальная установка

1. Требуется Node.js 22.13 или новее. Установите зависимости: `npm ci`.
2. Скопируйте `smtp.env.example` в `smtp.env` в корне репозитория.
3. Заполните `SMTP_EMAIL`, `SMTP_APP_PASSWORD`, `PUBLIC_BASE_URL` и `PRIVACY_CONTACT`. Для SMTP по умолчанию используются `smtp.gmail.com` и порт `465`. Для другого провайдера задайте его хост и порт; порт `587` использует STARTTLS.
4. `PUBLIC_BASE_URL` должен содержать уже существующий публичный HTTPS-адрес игры. Шаблон не настраивает Funnel.
5. Выполните `npm run workshop`. При первом запуске создаётся приватный `.env` со случайными `ADMIN_PASSWORD` и `PIN_PEPPER`. Пароль ведущего найдёте в `.env`; в консоль он не выводится. При последующих запусках существующий `.env` сохраняется без изменений.

`npm run workshop` запускает сервер в текущем терминале. На Pi постоянную работу обеспечивает существующая служба systemd, а не открытое окно терминала.

## Проверка перед мероприятием

Войдите в Host, в блоке Email readiness отправьте тест на свой адрес и проверьте входящие и спам. Если задан отдельный `EXERCISE_SMTP_EMAIL`, также проверьте отправителя Security exercise. Оба поля отдельного аккаунта должны быть заполнены; иначе оставьте оба пустыми, чтобы использовать основной SMTP.

В начале пятого раунда учебное письмо ставится в очередь каждому зарегистрированному игроку, включая тех, кто ещё не вошёл. Поздно зарегистрированные участники пятого раунда также получают письмо. Отдельное согласие в старом поле аккаунта больше не ограничивает эту рассылку. Ссылка ведёт на `/phishing`, где написано «Oops, hello! This was phishing». Там нет полей ввода и сбора учётных данных. Старые ссылки `/?security=1` тоже продолжают работать.

После завершения сессии все получают финальный отчёт, подтверждают OK и возвращаются на главный экран с кнопкой повторного открытия. Email содержит персональное обращение, роль, результаты деревни по раундам, имена совета и приватную ссылку на сохранённый отчёт.

«Reset game» доступно после завершения. Нужны подтверждение, точная фраза `RESET FINISHED GAME` и пароль ведущего. Сброс не удаляет финальные архивы, очередь итоговых писем, SMTP или доступ ведущего. Данные активной сессии удаляются одной транзакцией; повторный запрос со старым идентификатором отклоняется.

Архивы содержат имена и роли и сохраняются после сброса для доступа к отчётам. Приватная ссылка даёт доступ к своему отчёту: её нельзя публиковать. Политику хранения архивов и резервных копий определяют организаторы. Это не кнопка полного удаления персональных данных.

Итоговые письма повторяются при временной ошибке до 7 дней; PIN и учебные письма — до 15 минут. Постоянный отказ провайдера и истечение срока видны в журнале доставки. SMTP не гарантирует единственную доставку при обрыве после приёма письма: используется стабильный Message-ID, но провайдер может доставить повтор. Для Resend применяется ключ идемпотентности. Статус accepted означает приём провайдером, а не подтверждение получения во входящих.
