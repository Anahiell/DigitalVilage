# Быстрый запуск в Хорватии

Код готовится под уже настроенную малинку: пользователь `robot`, папка `~/projects/DigitalVilage`, Node 24, Tailscale и служба `digital-village`. Удалённо малинка в этой проверке не менялась. Для запуска нужны питание, настоящий интернет и выполнение команды ниже.

## 1. Куда подключить малинку

- Подключи её блок питания к **USB-C питания**. Сам Raspberry Pi подключи **Ethernet-кабелем в LAN-порт роутера**, у которого работает интернет. Существующий настроенный Wi-Fi тоже подойдёт; Ethernet обычно проще для мероприятия.
- Ноутбук ведущего подключи к интернету, проектор — HDMI к ноутбуку. Страницу проектора удобнее открыть на ноутбуке отдельной вкладкой. HDMI малинки нужен только для прямой работы с ней, если нет SSH.
- Малинка может остаться дома: тогда она должна всё время получать питание и интернет. Из Хорватии игра открывается по публичному адресу. Если привезёшь её с собой, подключи к местному роутеру; не нужно настраивать проброс входящих портов.
- Гостиничная сеть с окном «принять условия» может не дать малинке интернет. Если это так, используй доступный обычный роутер/мобильный интернет, с которым малинка действительно выходит в сеть. У участников тоже должен работать интернет.

## 2. Обновить и запустить

Открой терминал **на малинке** — локально либо через уже настроенный SSH/Tailscale. Если идёт старая тестовая игра, сначала нажми **Pause**.

Скопируй весь блок:

```bash
cd ~/projects/DigitalVilage &&
git fetch origin main &&
git show origin/main:deploy/update-pi.sh > /tmp/digital-village-update.sh &&
bash /tmp/digital-village-update.sh "$PWD"
```

Скрипт сам обновит `main` без удаления твоих правок, сохранит старый сгенерированный lockfile при необходимости, сделает приватную резервную копию базы и `.env`, проверит новую версию на временных данных, настроит автозапуск и HTTPS. Для `sudo` может понадобиться пароль пользователя **на самой малинке**. Установка зависимостей требует интернета и может занять несколько минут.

Твои существующие SMTP-настройки, пароль ведущего и секрет PIN сохраняются. Слабые значения `CHANGE_ME` заменяются случайными; настоящий `PIN_PEPPER` нельзя менять — старые PIN перестанут работать. Если отправитель или контакт организатора не настроен, скрипт остановится с конкретной причиной. В `.env` нужно указать настоящие значения; не присылай секреты в чат.

Существующий Observatory на `https://robobrain.taild17717.ts.net` сохраняется. Игра использует отдельный адрес, ожидаемо:

**https://robobrain.taild17717.ts.net:8443/**

Скрипт получает фактическое DNS-имя из Tailscale; если оно изменилось, используй адрес из проверки/приглашения ведущего. Если 8443 занят другой службой, скрипт остановится, не заменяя её. Не выполняй `tailscale funnel reset`: он удаляет и чужие маршруты.

В конце должны пройти локальная и публичная проверки. Если локальная прошла, а публичная ещё не открывается, проверь интернет, статус Funnel и повтори `npm run doctor`: изменение DNS может применяться не сразу. Служба при этом уже работает.

## 3. За пять минут до участников

1. Открой публичный адрес **на телефоне с мобильным интернетом**. Это проверяет внешний доступ, а не только местную сеть.
2. Вкладка **Host** → войди своим `ADMIN_PASSWORD` из приватного `.env`.
3. Раскрой **Invitations, email checks and participant support**. Выбери **PIN delivery**, затем **Security exercise** и по очереди нажми **Send one delivery test** на свой настоящий адрес; проверь входящие и спам. Затем зарегистрируй один тестовый аккаунт и проверь PIN и повторную отправку после отсчёта. Кнопка проверки и журнал показывают принятие письма провайдером; приход подтверждаешь ты.
   Статус **queued** означает, что запрос сохранён и ещё не подтверждён провайдером. Малинка повторяет временные сбои с паузами до 15 минут и продолжает после перезапуска. Тело письма с PIN хранится зашифрованно. Не меняй `PIN_PEPPER`.
4. Если почта тормозит: **Enrol a participant in person** → настоящие имя/email, село, свободная роль, подтверждение присутствия → **Create account & show private PIN**. Передай PIN лично. Для уже существующего аккаунта используй выдачу нового PIN в списке участников. Выдача PIN ведущим отменит отложенную замену из почтовой очереди. Не показывай приватный PIN на проекторе.
5. QR уже создаётся самой малинкой. Открой **Projector** в отдельной вкладке: в ожидании он показывает QR и ссылку. Участник сканирует камерой, регистрируется и входит. Отдельный сервис QR и приложение Tailscale на телефонах не нужны.

Если меняешь `PUBLIC_BASE_URL`, перезапусти службу и заново открой приглашение: QR всегда кодирует настроенный адрес. Сам QR не создаёт домен или интернет.

## 4. Как провести игру

| Раунд | Управление и проверка |
|---|---|
| 1 | Игроки покупают улучшения. На 10-й активной минуте кризис один раз снимает 30% текущего бюджета каждого села. Ведущий может вызвать его раньше кнопкой Funding −30%. Повторного списания нет. |
| 2 | Новости заново составляются из реальных итогов первого раунда. Проверяют факты, подпись и печать по официальным бюллетеням; можно выбрать до шести новостей других сёл. Reveal news показывает объяснения. |
| 3 | Команда публикует кампанию, проверяя условия использования картинок. Для материала CC BY нужна указанная подпись. Конфликт двух редакторов сохраняет черновик и предлагает загрузить новую публикацию. |
| 4 | Распределяют четыре обычные задачи. На 4-й минуте приходят две срочные. Подходящая роль и мэр работают быстрее; несколько задач делят время человека. Помогать можно чужой задаче раз в минуту. Успех требует всех шести. |
| 5 | Четыре задания по безопасности сохраняют ответы каждого участника; объяснения открываются после завершения. Отдельное учебное письмо отправляется только согласившимся участникам; упражнения доступны на сайте всем. |

**Close round & view results** закрывает раунд и показывает сохранённую статистику всех сёл, имена/должности и историю по результатам. Таймер делает то же автоматически. Экономика стоит на паузе обсуждения; **Open next round** продолжает игру. После пятого — **Finish simulation** и общая история. Архив **Round reports** остаётся доступен. После перезапуска активная игра возвращается на паузе: продолжи кнопкой **Resume**.

Для двухчасовой встречи: 10 минут регистрации, активные раунды 18/18/18/28/13 минут, по 2 минуты обсуждения после каждого, 5 минут общего финала. Максимальные таймеры 20/20/20/30/15 минут вместе с обсуждениями потребуют больше двух часов.

## 5. Нормальное имя и почта

**Бесплатное красивое имя:** предлагаю `ruralem-play.pages.dev`. Код HTTPS-шлюза уже в проекте; имя ещё не зарегистрировано. Нужен твой бесплатный Cloudflare-аккаунт: [пошаговая настройка](FREE_DOMAIN_RU.md). Игра и база остаются на малинке; существующий Observatory сохраняется. У бесплатного шлюза общий лимит 100 000 запросов в сутки на аккаунт. Для 30 участников + ведущего + проектора на два часа ожидаются 65–75 тысяч запросов, включая действия; это расчёт, не измерение в Cloudflare.

**Уже подготовленный запасной адрес:** текущий Tailscale Funnel с `:8443`. Короткое имя не заменяет питание и интернет. После активации Pages укажи фактический адрес в `PUBLIC_BASE_URL` и перезапусти службу по инструкции; QR обновится автоматически. Следующие обновления малинки сохранят выбранный адрес.

**Почта:** текущий Gmail продолжает отправлять PIN; покупать домен для него не надо. Для учебных писем можно бесплатно завести другой Gmail и локально добавить `EXERCISE_SMTP_EMAIL` / `EXERCISE_SMTP_APP_PASSWORD` в приватный `.env`, затем перезапустить службу. Без этих настроек отправитель общий, что видно ведущему. Очередь отдаёт PIN приоритет и оставляет для них один из четырёх потоков при учебной рассылке. Если задан отдельный отправитель, его ошибка не переключает упражнения на PIN-аккаунт.

Запросы сохраняются зашифрованно до отправки; временные ошибки повторяются до 15 минут, в том числе после перезапуска. Постоянный отказ останавливает повтор. Статус accepted подтверждает принятие провайдером, а приход проверяется в настоящем ящике. Стопроцентное попадание во входящие обещать нельзя: фильтры получателя могут заблокировать письмо. Если письмо не пришло, ведущий выдаёт PIN лично, а задания по безопасности доступны на сайте. Бесплатный адрес `pages.dev` не даёт почтовый ящик или отправляющий домен Resend.

## Если что-то не открылось

В папке проекта:

```bash
npm run doctor
systemctl status digital-village --no-pager
journalctl -u digital-village -n 50 --no-pager
tailscale funnel status
```

`doctor` не печатает пароль и не отправляет писем. Проверяй: питание → интернет → локальная служба → публичный HTTPS → письмо. Локальное здоровье: `http://127.0.0.1:3000/healthz` должно вернуть `{"ok":true,"app":"digital-village"}`. Не удаляй `storage/` и `.env`; там игра и доступы. Приватные резервные копии лежат в `backups/`.
