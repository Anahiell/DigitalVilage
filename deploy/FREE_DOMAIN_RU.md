# Бесплатный адрес для игры на малинке

Предлагаемое имя — **`ruralem-play.pages.dev`**. Это бесплатный поддомен Cloudflare Pages с HTTPS. Имя ещё не зарегистрировано: Cloudflare проверит доступность при создании проекта. Если оно занято, выбери `ruralem-croatia` и используй фактический адрес из панели. Покупка домена не требуется.

На Pages работает маленький HTTPS-шлюз из `deploy/free-domain/public/_worker.js`. Он передаёт запросы на **`https://robobrain.taild17717.ts.net:8443`**. Сама игра, база, PIN и отправка почты остаются на малинке. Существующий Observatory на порту 443 сохраняется. Малинка должна быть включена, иметь интернет и работающий Funnel на 8443.

## 1. Создать адрес в своём Cloudflare

1. Войди в свой бесплатный аккаунт [Cloudflare](https://dash.cloudflare.com/). Открой **Workers & Pages → Create application → Pages → Connect to Git**. Выбери GitHub и дай доступ к репозиторию `Anahiell/DigitalVilage`.
2. Имя проекта: `ruralem-play`; ветка: `main`; framework preset: **None**; build command: оставь пустым; root directory: **`deploy/free-domain`**; build output directory: **`public`**. Если выбрал другое имя проекта, измени `name` в его `wrangler.jsonc` на то же значение. Не выбирай платный Workers plan.
3. Нажми Deploy. Конфигурация задаёт compatibility date `2026-10-18` и `allow_custom_ports`: порт **8443 обязателен**, иначе запрос может уйти на другой сервис малинки. Не заменяй его на 443.
4. Проверь реальный адрес опубликованного проекта в панели. Пока малинка не подключена, шлюз честно отвечает 503. Это не подтверждает поломку игры.
5. Если фактическое имя малинки отличается, измени **`vars.PI_ORIGIN`** в `deploy/free-domain/wrangler.jsonc` на её полный HTTPS-адрес **с `:8443`**, сохрани изменение в GitHub и дождись нового Deploy. Если имя прежнее, менять ничего не нужно. Конфигурация в Git управляет этими настройками; редактировать ту же переменную в панели при таком режиме нельзя. Шлюз принимает только корневые HTTPS-адреса `*.ts.net` на разрешённых Funnel-портах.

Альтернатива без подключения GitHub: **Pages → Direct Upload**, имя `ruralem-play`, загрузить **содержимое** `deploy/free-domain/public` вместе с `_worker.js` и `_routes.json`. Установи ту же compatibility date и флаг `allow_custom_ports` в настройках проекта, затем заново разверни. При изменившемся имени малинки задай `PI_ORIGIN` в настройках переменных этого проекта. Режим `_worker.js` поддерживает Direct Upload; корневой Node-сервер загружать в Pages не нужно.

## 2. Подключить малинку

Сначала подключи питание/интернет и выполни обновление из [ARRIVAL_RU.md](ARRIVAL_RU.md). Оно создаёт Funnel 8443. После успешного создания **именно `ruralem-play.pages.dev`** выполни на малинке:

```bash
cd ~/projects/DigitalVilage &&
node deploy/pi-config.mjs --configure --url https://ruralem-play.pages.dev &&
sudo systemctl restart digital-village &&
npm run doctor
```

Если Cloudflare выдал другое имя, замени адрес в команде на фактический. Не устанавливай предложенное имя до его успешного создания. Конфигурация сохраняет пароль ведущего, `PIN_PEPPER`, почту и базу. Следующие обновления малинки сохранят выбранный адрес, продолжая поддерживать Funnel на 8443.

Открой новый адрес на телефоне через мобильный интернет. Войди ведущим, затем проверь регистрацию/PIN и вход участника через **этот же адрес**. Прежние браузерные сессии с другого домена не переносятся: нужно войти заново. QR в приглашении и проекторе будет содержать новый адрес после перезапуска. Браузерные действия проверяют Origin, поэтому участникам выдавай один выбранный адрес.

## 3. Лимит бесплатного тарифа и запасной путь

У Workers Free — **100 000 динамических запросов в сутки на аккаунт**, общий лимит с другими Workers/Functions, сброс в 00:00 UTC. Через этот шлюз запросы игры считаются динамическими. При текущем обновлении каждые 3,5 секунды 30 участников + ведущий + проектор за два часа создадут примерно **66 тысяч опросов**; с входами и действиями ориентир **65–75 тысяч запросов**. Это расчёт, не замер Cloudflare. Дополнительные вкладки и время подготовки увеличивают расход; закрывай ненужные вкладки и проверь счётчик в панели до встречи. Встроенный платный upgrade для этого проекта не включается.

Если лимит исчерпан или Pages недоступен, на малинке верни текущий Funnel-адрес:

```bash
cd ~/projects/DigitalVilage &&
node deploy/pi-config.mjs --configure --url https://robobrain.taild17717.ts.net:8443 &&
sudo systemctl restart digital-village &&
npm run doctor
```

Если Tailscale показывает другое имя, используй его. Заново открой приглашение, раздай обновлённый QR и войдите с нового адреса. База, роли, PIN и сохранённый раунд остаются; активный раунд после перезапуска нужно продолжить кнопкой Resume. Сам бесплатный адрес не даёт резервного интернета или питания.

## 4. Почта отдельно от адреса сайта

`pages.dev` не предоставляет почтовый ящик и контроль DNS для верификации отправителя в Resend. Уже настроенный Gmail может отправлять PIN без покупки домена.

Для учебного письма пятого раунда можно использовать **другой Gmail**: владелец включает 2FA, создаёт пароль приложения и локально добавляет в приватный `.env`:

```dotenv
EXERCISE_SMTP_EMAIL=адрес_второго_аккаунта
EXERCISE_SMTP_APP_PASSWORD=его_пароль_приложения
```

Подставь настоящие значения на малинке; не присылай пароль в чат. Перезапусти `sudo systemctl restart digital-village`. Это рабочая необязательная настройка, а не уже созданный ящик. Без неё учебные письма используют текущего отправителя PIN. При явно заданном отдельном отправителе его ошибки **не переключают учебные письма на PIN-аккаунт**. Очередь даёт PIN приоритет и резервирует один из четырёх потоков от учебной рассылки.

В Host → **Invitations, email checks and participant support** выбери по очереди **PIN delivery** и **Security exercise**, отправь по одному тесту на адрес, чьи входящие и спам ты проверишь. Кнопка проверяет выбранного отправителя; статус accepted означает принятие провайдером. После этого проверь настоящую регистрацию и повтор PIN. Упражнения пятого раунда доступны на сайте даже при блокировке письма, а PIN ведущий может выдать лично. Получатели могут фильтровать учебную рассылку; стопроцентное попадание письма во входящие не гарантирует ни один этот адрес или почтовый провайдер.
